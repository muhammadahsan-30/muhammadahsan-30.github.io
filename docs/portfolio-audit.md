# Portfolio audit

Phase 1 of the portfolio redesign. **No production code changed.** This document inspects
what is deployed today and says what is wrong with it; `docs/portfolio-design-spec.md`
says what to do instead.

Inspected: all five pages (`index`, `projects`, `experience`, `contact`, `404`),
`assets/style.css` (567 lines), `assets/site.js`, the deployed site over HTTP, every
outbound project link, mobile rendering at 390px, accessibility structure, motion
handling, and the current shipped state of the OOH Campaign Performance Analyzer.

---

## 1. What is already strong — do not break it

This has to be said first, because the instinct with a redesign is to replace things that
are working.

**The visual identity is genuinely distinctive.** Newsreader over Inter, sienna
(`#8a3f2b`) and deep teal on cream paper, a 22px dot grid so cards sit *on* something,
hairline rules, numbered section heads. It reads editorial, not "developer portfolio
template". Most student portfolios are a dark hero with a gradient; this is not that, and
that is an asset worth preserving.

**The engineering underneath is careful.** Dark mode is a considered re-selection rather
than an inversion, with comments explaining why `--accent-ink` flips and why the dot grid
is *lower* contrast in dark. `prefers-reduced-motion` is honoured. Images carry `alt` and
explicit dimensions. Every external link has `rel="noopener"`. `site.js` degrades
gracefully without `IntersectionObserver`.

**The writing is specific.** "I read everything and I reply to everything." The Nishat
Sutas section separating public filings from his own contribution. The note that CAD 19.5M
is capital one partner deployed, *not* a deal he led. That restraint is rare and it is
credible.

**Mobile is clean.** 390px: `scrollWidth` equals viewport width, zero overflowing
elements.

**Every outbound link resolves (200).** BarakahLink, both GitHub repos, the analyzer.

## 2. The 5 / 30 / 120-second test

### 5 seconds — above the fold

A reader sees: a name set large in serif, a portrait, one sentence, four large figures,
five buttons.

**What lands:** this is a Waterloo Mathematics and Business student, available Jan–Apr
2027, who has worked with real money.

**What does not land:** what he is *for*. The single best sentence on the entire site —
*"I build valuation models, plan media campaigns, and write the tools that measure them"* —
is set at body size, below a very large name, beside a competing portrait. It is the
positioning statement and it is styled as a caption.

**And one thing lands wrongly.** See §3.

### 30 seconds — scrolling the homepage

Status rows (KPMG, Kinetic, Building, Outside), then three "Selected work" text rows, then
the published article.

**What lands:** real brands — KPMG, WPP/GroupM — and a published newspaper article, which
is unusually strong third-party validation for a second-year student.

**What does not land:** the flagship. The analyzer is the third of four status rows, then
one of three equal-weight text rows with no image, described in two sentences that stopped
being accurate three development phases ago. A reader at 30 seconds has no idea there is a
live, seven-view analytical product behind that link.

### 2 minutes — into Projects

**What lands:** the OOH card is good — live embedded iframe preview, real figures bound to
the payload, source link. The Smog article has a mockup and a real external link.

**What does not land:** four projects at identical visual weight, in an order that implies
equal importance. The fourth (Justdiggit) has no artifact, no link, no figures — and sits
in the same card frame as the flagship.

## 3. The most serious problem: synthetic data is presented as a real-world metric

The homepage stat band is four figures in identical styling:

| Figure | Label | What it actually is |
|---|---|---|
| CAD 19.5M | Capital in venture valued | **Real** — public filing, Nishat Mills' deployed capital |
| CAD 1M+ | Media spend reconciled | **Real** — Kinetic, PKR 200m across three campaigns |
| **CAD 5.4M** | **Tracked by my pipeline** | **SYNTHETIC** — generated by `generate_data.py`, seed 42 |
| 1 of 2 | Interns selected | **Real** |

A recruiter reads four equivalent claims about real-world scale. One of them is invented
data from a portfolio project, and nothing in the band says so.

This is the single highest-severity finding in the audit. Not because it is dishonest in
intent — the project page and the analyzer itself are scrupulous about labelling the data
synthetic, more so than most — but because **this particular placement strips the label
off.** The one number a sceptical interviewer is most likely to probe ("tell me about this
5.4 million") is the one that dissolves on contact.

It is also trivially fixable, and the fix makes the site *stronger*: a separate, clearly
framed "what I built" measure reads as more impressive than a laundered one, because it
shows judgement.

## 4. Five recruiter lenses

| Lens | Currently sees | Currently misses |
|---|---|---|
| **Analytics** | Python, SQL, SQLite, pandas, pytest in the stack chips; a live dashboard | That the analyzer contains real analytical reasoning — gross vs net, masking, detection timing, a documented null result. None of it is on the portfolio. |
| **Business / marketing** | Kinetic, WPP/GroupM, Katalyst, 12,000+ sites, media spend reconciliation, an OOH product | The strongest story — *he noticed the problem on the job and built the fix* — is implied by one clause ("the reporting tool I wanted while inside the agency") and never told as a sequence |
| **Finance** | KPMG Deal Advisory, DCF at 16.38% WACC, three-statement modelling, Nishat Sutas | Nothing. This lens is the best-served on the site. |
| **Software / data** | Live app, two GitHub repos, TypeScript, Gemini API, vanilla JS | Any sense of engineering rigour: 44 unit tests, a validated pipeline, SQL/Python cross-checks, a design system — all exist, none surface |
| **General** | A credible, well-written, good-looking site | A one-line answer to "what is he?" |

**The breadth problem.** Finance (KPMG) + media (Kinetic) + analytics/product (analyzer) +
AI/dev (BarakahLink) + research/writing (Smog, Justdiggit). Without a stated thread, a
recruiter pattern-matches breadth to *undecided*. The thread exists; the site never says it.

## 5. Positioning

**Current implicit positioning:** "Mathematics and Business student who does finance, media
and tools."

**The brief's proposed thread:** *"using analytical, technical, and business skills to
solve practical business problems."* This is true, and it is what every analytics candidate
writes. It describes a category, not a person.

**What the evidence actually shows.** Look at the pattern across four of the entries:

- At KPMG he did not only model — he worked *down to the underlying journal entries*.
- At Kinetic he did not only analyse the market — he rotated through five departments and
  reconciled the invoices.
- At the agency he noticed reconciliation was manual, and then **built the tool**.
- For Smog he did not write an opinion piece — he built a cost-benefit model first, then
  argued it on the commercial case because that is what persuades a media owner.

The repeated move is: **get inside how something actually works, then build the thing that
was missing.** That is considerably rarer than "analytical skills", it is provable from the
existing content, and it does not narrow him to one role — it explains why the breadth is
coherent rather than scattered.

### Recommended positioning line

> **I learn how a business works, then build what it's missing.**

*(Refined during spec v2. The earlier draft ended "…build the thing that measures it",
which was narrower than the evidence — BarakahLink and the Smog feasibility model are not
measurement tools. "What it's missing" covers all of it and remains falsifiable.)*

with the existing subline kept almost verbatim beneath it, because it is already excellent:
*Valuation models at KPMG, media campaigns at a WPP/GroupM agency, and the tools that
measure them.*

**Alternates**, if the above reads too confident:

- *"Business problems, taken down to the data — and back up to a decision."*
- *"I work where the numbers are made."*

The first is recommended. It is a claim the Kinetic → analyzer arc proves outright.

## 6. Project hierarchy

Currently four projects, equal weight, numbered 01–04. Recommended:

### FEATURED — OOH Campaign Performance Analyzer

The only project that is simultaneously a **live product**, an **analytical argument**, and
**evidence of engineering discipline**. It is also the only one that connects directly to
paid experience. Nothing else on the site demonstrates Python, SQL, data modelling, testing,
visualisation, frontend implementation, product thinking and domain knowledge in one
artifact.

It should get a full case-study treatment, not a card.

### FEATURED (second) — Smog-Eating Billboard

Kept prominent for one reason the others cannot match: **third-party publication**. A
national newspaper ran it. For a second-year student that is external validation, and
validation is worth more than scope. It is also genuinely good reasoning — the pivot to
arguing on cleaning-cycle cost rather than environmental benefit is the kind of thinking
interviewers remember.

### SECONDARY — BarakahLink

Live, real stack (TypeScript, Gemini, Leaflet), a thoughtful constraint (SMS access where
connectivity is the barrier). Demonstrates range into applied AI and product. But it is
AI-assisted, less analytically deep, and has no measured outcome. Card treatment, not case
study.

### ARCHIVE — Justdiggit Funder Research

No artifact, no link, no figures, no outcome. It is real work and worth mentioning, but as a
**line in Experience**, not a numbered project section carrying the same frame as the
flagship. Keeping it at project weight dilutes the other three.

## 7. The OOH project is described three phases out of date

The portfolio describes a product that no longer exists — an earlier, smaller version of it.

| Portfolio says | Actually true now |
|---|---|
| "ranks it mid-flight, by prorating each contract to the days elapsed, and prices the shortfall" | Still true, but this is now roughly a quarter of what the product does |
| — | **Gross vs net shortfall and masking**: the book reads −2.1% while 10.5m impressions are short across 227 placements, 14% masked |
| — | **In-flight fault detection**: 98.1% of faults recovered from delivery data alone, median 0-day onset error |
| — | **Detection timing**: median 4 days to flag against 31 days to reconciliation, 35 days of flight typically still remaining |
| — | **Live vs completed separation**: 21 live issues ranked by preventable exposure, 61 completed shortfalls for reconciliation |
| — | **Two named exposure measures** over two populations, deliberately not interchangeable |
| — | **44 unit tests**; SQL and Python agree to the dollar |
| — | Seven views, light/dark, CVD-validated palette, an explain layer, a flight timeline |
| "Building" (homepage status row) | **Feature-frozen and live** |

The projects-page card is current (figures bind to the live payload, Chart.js was removed
from the chips). The **homepage** is where the staleness sits: the "Selected work" row and
the "Building" status line.

### The origin story is the most valuable unused asset

The brief is right that this matters. The sequence —

> worked inside a WPP/GroupM out-of-home agency → reconciled CAD 1m+ of media spend by hand
> → noticed the problem was structural, not clerical → modelled it → built the analyzer

— is the single most compelling thing on the site, and it is currently one subordinate
clause. Told as a sequence it demonstrates commercial awareness, initiative and technical
capability in one move, and it is the proof of the recommended positioning line.

## 8. Technical and accessibility findings

| Finding | Severity | Detail |
|---|---|---|
| **No skip link on any page** | Medium | Keyboard users traverse the full nav on every page. The analyzer app has one; the portfolio does not. |
| **No `aria-current` on nav** | Medium | Active page is signalled by `class="on"` — visually only. Screen readers get no "you are here". |
| Stat band mixes synthetic and real | **High** | §3 |
| Homepage OOH copy stale | Medium | §7 |
| "Building" status now wrong | Low | Project is frozen and live |
| Four projects, equal weight | Medium | §6 |
| Homepage `.status` rows duplicate Experience | Low | Not a defect in isolation, but once the "One thread" section tells the Kinetic story and the Experience page carries the roles, these rows become a third telling of the same facts. Spec v2 removes them. |
| Flagship has no image above the fold | Medium | The strongest asset is invisible until Projects |
| `resume.pdf` predates the analyzer work | Low | Dated 11 Sep; the project has changed substantially since. Flagged only — **not touched**, per instruction |
| No Power BI claim anywhere | ✅ Correct | Verified: zero references across all pages. This is the correct current state and must stay that way until the artifact exists |

Nothing was found in these categories: broken links, missing alt text, missing image
dimensions, layout overflow at 390px, missing `rel="noopener"`, unhandled reduced-motion.

---

## 9. What a redesign should and should not change

**Should not change:** the colour system, the type pairing, the dot grid, the editorial
tone, the restraint in the writing, the Nishat Sutas public-context treatment, the dark
mode implementation.

**Should change:** the hierarchy. This is a *structural* redesign, not a visual one. The
site looks good and says the wrong things in the wrong order.

**Must change:** the synthetic figure in the stat band (§3).

---

## 10. Questions that genuinely block implementation

1. **Windows access for Power BI Desktop.** Phase 4 cannot start without it. If there is no
   realistic Windows machine, VM, lab or cloud option, the recommendation is to stop at the
   specification rather than fake an artifact — and Tableau Public becomes the macOS-native
   alternative that still yields a link a recruiter can open.

**Resolved since this audit was written** (see `portfolio-design-spec.md` v2):

- *Dedicated case-study page?* **Yes — `ooh.html`,** reached from the homepage and Projects,
  not added to the nav. The flagship uses a *navigate* affordance ("Explore the case study
  →") while every other project uses an *expand* affordance ("View details ↓"). The
  difference in affordance is itself the hierarchy signal, and it avoids giving OOH three
  competing depth levels.
- *Justdiggit?* **Move to Experience**, collapsed by default.

Nothing else blocks.
